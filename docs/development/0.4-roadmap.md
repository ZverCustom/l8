# L8 v3: 0.4 development stages

Branch `fw-v3-next`, based on reviewed `497b8e4` (0.3.4).
PCB unchanged. All new behavior is unqualified on hardware until the bench below.

1. Build identity from Git, RAM journal, common engine predicate, lazy PSRAM fire buffer.
2. Time-based per-strip animation, schema migration, visual meter smoothing/peak hold.
3. Measured current limiting and bounded overload recovery; hardware faults remain latched.
4. Transactional live preview and explicit persistence; AP-first Wi-Fi, captive portal, push status.
5. Optional LCD_CAM/DMA parallel output, native waveform tests, both backends build.
6. Integration checks, documentation, bench qualification before making DMA the default.

## Release gates

- USB boot logs and existing 0.3.4 Wi-Fi/OTA checks remain outstanding.
- Current calibration with meter; load step, idle current that cannot be dimmed,
  short, switch thermal fault, I2C loss, brownout, three failed retries and sustained recovery.
- Two phones, visible/hidden/disconnected tabs; preview vs save vs reset; no unsaved
  preview in reboot/backup; AP without home network; manual reconnection and captive detection.
- Oscilloscope on all eight physical DATA pins: bit timing, channel ordering,
  unequal strip lengths, power gating during DMA, maximum frame, OTA/flash overlap.
- No claim of measured latency/FPS until measured on the board.

RMT remains the default and retains its flash exclusion. Experimental DMA must
not be used to justify removing the RMT patch or hardware interlocks.
