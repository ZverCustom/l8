# L8 v3: первый запуск от USB

Отдельная диагностическая прошивка для ESP32-S3-WROOM-1U-N16R2 на PCB v3.
Полная прошивка v3 находится в [корневом проекте](../../README.md).
В этой отдельной диагностике нет Wi-Fi, веб-интерфейса, OTA и управления лентами.

**Проверено на плате 2026-11-20:** ESP32-S3 rev 0.2, flash 16 МБ, PSRAM 2 МБ,
тест 64 КиБ PSRAM, PCA9555 и свежие измерения IMU — PASS. За 20 секунд получено
10 последовательных отчётов без ошибок и повторных перезапусков. Питание — только
USB. [Лог](reports/2026-11-20-usb.log), [результаты и SHA256 прошивки](reports/2026-11-20-usb.json).

**Следующий этап, 2026-11-20:** при подключённых внешних 12 В и USB показания VBAT
11.91–11.92 В; IGN=0, HOLD=0, выходы выключены. Десять отчётов без ошибок.
Это подтверждает чтение VBAT, но не работу DC/DC: логика может питаться от USB,
а IGN ещё не включён. [Лог](reports/2026-11-20-12v-ign-off.log),
[результаты](reports/2026-11-20-12v-ign-off.json). Надпись `USB only` в логе относится
к режиму диагностической прошивки, а не к определению источника питания.

Подключение для этой проверки: **только USB**, без 12 В и IGN.
Диагностика удерживает HOLD и восемь DATA в нуле, выключает все LED IN, DEN и
питание датчиков 5V_SENS, держит CAN в silent. Подтяжки IN1–3 отключены.
Выходные регистры PCA9555 сначала записываются и проверяются, только затем
порты переводятся в выходы. Индикатор статуса остаётся выключенным.

## Сборка и запуск

На этом Mac одна команда загружает диагностику и сохраняет 20 секунд лога:

```sh
~/.platformio/penv/bin/python ~/Documents/Code/ZVER/L8/diagnostics/v3-usb/flash_and_log.py
```

Она выбирает единственный ESP32 USB JTAG/serial (`303A:1001`). Если таких плат
несколько, добавьте `--port /dev/cu.usbmodem1101`. Лог: `.pio/usb-bringup.log`.
Повторное чтение без прошивки: тот же скрипт с `--capture-only`.

Отдельные команды PlatformIO:

Из этой папки:

```sh
~/.platformio/penv/bin/pio run
~/.platformio/penv/bin/pio run -t upload --upload-port /dev/cu.usbmodem1101
~/.platformio/penv/bin/pio device monitor --port /dev/cu.usbmodem1101 -b 115200
```

Загрузка заменяет приложение на плате диагностикой. Старый `esp32s3box/firmware.bin`
из ветки `fw-v2` для v3 не подходит. Этот проект использует `qio_qspi`
(Quad PSRAM), 16 МБ flash и native USB CDC. Если порт изменится, его имя покажет
`~/.platformio/penv/bin/pio device list`.

## Что должно появиться в логе

Отчёт повторяется каждые две секунды, поэтому монитор можно открыть после загрузки:

- ESP32-S3, flash 16 MB.
- PSRAM `chip=2048 KB`, `capacity=PASS`, `64 KB scratch test=PASS`: проверка
  двух шаблонов в 64 КиБ, не полный тест всей памяти. `usable` немного меньше
  физического объёма (около 2045 КиБ): часть памяти занимает аллокатор.
- `HOLD=0`, `IGN=0`, `5V_FAULT_N=1`; VBAT близко к нулю при питании только от USB.
- PCA9555 `@0x20: PASS`, `OUT=0x2000 CFG=0x0000 PIN=0x2000`.
- LSM6DS3TR-C `@0x6A`, `WHO=0x6A`, `init=PASS`, затем новые измерения.
  На неподвижной плате длина вектора ускорения около 1 g, вращение около 0 dps.

Это проверка запуска MCU, небольшой области PSRAM, связи I2C и IMU.
Она не проверяет выходное напряжение силовых ключей, измерение тока под нагрузкой,
работу DC/DC от 12 В, IGN/HOLD, CAN, K-line или Wi-Fi. Для них нужен следующий
этап проверки платы с соответствующим питанием и подключениями.
